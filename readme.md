# Распределенная микросервисная система интернет магазина

Проект представляет собой прототип распределенной событийно-ориентированной системы  для управления сущностями каталога, корзины и обработки заказов. Система построена на базе микросервисной архитектуры с использованием контейнеризации, механизмов кэширования в памяти и асинхронного обмена сообщениями.

##  Архитектура проекта

Система состоит из следующих изолированных компонентов, развернутых в единой Docker-сети:

* **`catalog-service` (Flask):** Синхронный REST API для управления номенклатурой товаров. Включает оптимизацию чтения через in-memory кэширование (`TTLCache`).
* **`cart-service` (Flask):** Модуль ведения локальных корзин пользователей с неблокирующим триггером оформления заказа.
* **`order-service` (Flask / Python):** Сервис управления жизненным циклом заказов.
* **`order-worker` (Python / Pika):** Фоновый асинхронный воркер, обрабатывающий очередь checkout-транзакций и изолирующий СУБД от пиковых нагрузок интерфейса.
* **`catalog-worker` (Python / Pika):** Компонент распределенной Саги, отвечающий за асинхронную проверку и атомарное списание остатков товаров на складе.
* **Брокер сообщений (RabbitMQ):** Транспортная AMQP-шина, координирующая обмен сообщениями и гарантирующая сохранность данных.
* **База данных (PostgreSQL):** Реляционное хранилище транзакционных данных микросервисов.

##  Результаты оптимизации производительности

В ходе профилирования и рефакторинга интеграционных интерфейсов система была переведена с блокирующих HTTP REST вызовов на гибридную модель (Кэш + AMQP). Результаты замеров Latency (времени отклика для клиента):

| Операция | До оптимизации (Синхронный REST) | После оптимизации (Кэш + AMQP) | Относительное ускорение |
| :--- | :--- | :--- | :--- |
| **Чтение каталога (`GET /products`)** | 20.40 ms | **8.29 ms** (RAM кэш) | **В 2.5 раза быстрее** |
| **Оформление заказа (`Checkout`)** | 35.88 ms | **10.21 ms** (Async AMQP) | **В 3.5 раз быстрее** |
| **Суммарный цикл ожидания клиента** | 56.28 ms | **18.50 ms** | **Быстрее на 67.1%** |

##  Запуск проекта

### Требования
* Установленный Docker и Docker Compose
* Python 3.10+ (для локального запуска тестов)

### 1. Клонирование и запуск инфраструктуры
Развертывание всех микросервисов, баз данных и очередей выполняется одной командой из корня проекта:

```bash
docker compose up -d --build
```
### 2. Проверка состояние компонентов
Убедиться, что фоновые асинхронные воркеры успешно инициализировали сессии с RabbitMQ:
```bash
docker logs -f order-worker
docker logs -f catalog-worker
```
### 3. Тестирование системы
Для верификации интеграционных сценариев и замера метрик задержек в папке `tests/`
